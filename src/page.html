    Research, design, limits & licences
    
A petri dish, not a verdict

    
Tangle asks one question: can useful global understanding emerge from recursively resolving tiny, locally scoped questions? This page is a runnable prototype of that loop. A fresh model invocation receives one bounded node plus only the evidence that node has seen. It may look something up, decompose the question, resolve it with a finding, or report that it is blocked. The harness owns the graph: it validates every proposal and refuses findings that cite evidence the model was never shown.

    
The simulation replays authored responses and evidence paragraphs; they are neither model output nor captured Wikipedia pages. Live mode runs a small Qwen3 model on your device through WebLLM and reads English Wikipedia as its only source.

    
How to use it on a phone

    
  1. Open this page in a browser that executes JavaScript. Simulation needs no internet.
  2. For live mode choose Local LLM + Wiki, then Check device. Start with Qwen3 0.6B.
  3. Use Wi-Fi for the model download. Press Download & load, wait for Ready, then start a graph and press Run.
  4. Allow each Wikipedia lookup, or tick the box to allow them for the whole run.
  5. Export the run before closing the page. Exports can be re-opened with Inspect JSON.

    
Model weights are cached by the browser, which needs a secure origin with storage. A downloaded file:// copy can usually run the simulation but often cannot keep a model; the served page over HTTPS or localhost can.

    
Design decisions

    
  • One serial, deterministic, depth-first scheduler. A parent is revisited only after all its children resolve; a blocked child leaves it unresolved. Edges express parent–child decomposition only.
  • Both modes share the same validator and episode runner. Simulation and live graphs are kept separate.
  • Findings and evidence are distinct records. A finding may be wrong; the evidence records what was actually read, with the Wikipedia revision where available.
  • Model output is grammar-constrained to a JSON action object. The validator then decides whether the content is acceptable.
  • Strange behaviour is recorded rather than patched. Repeated questions, awkward decompositions and unresolved branches are observations.
  • Safety limits bound every run: nodes, visits, depth, lookups per visit and model calls per visit.

    
Limits

    
Small local models may decompose poorly, repeat themselves, misread evidence or fail to return a useful finding. Keep the phone foregrounded; long sessions consume battery and can cause thermal throttling. This page is built from source with tests; see the repository for what is and is not covered.

    
Data and privacy

    
Run state stays in memory until you export it. There is no analytics or automatic upload. Exports contain prompts, source excerpts and responses, so inspect them before sharing. Wikipedia sees requested query terms and your network address. Model hosts see model-download traffic. Wikipedia content remains attributed to its article and contributors under CC BY-SA 4.0.
