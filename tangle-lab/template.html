    Research, design, limits & licences
    
A petri dish, not a verdict

    
This is a runnable, single-file Tangle prototype. It combines an offline demonstration with a live in-browser research loop. The demonstration’s JSON responses and evidence paragraphs were authored in advance; they are neither real model measurements nor captured Wikipedia pages. The live mode does not use those scripts.

    
How to use it on a phone

    
  1. Open this HTML in a browser that executes JavaScript, not a document-preview app. Simulation needs no internet.
  2. For live mode choose Local LLM + Wiki, then Check device. Start with Qwen3 0.6B.
  3. Use Wi-Fi for the model download. Press Download & load, wait for Ready, then start a graph and press Run.
  4. Allow each Wikipedia request, or opt into automatic lookups for that run. Stop cancels the current visit; Pause waits for it to finish.
  5. Tap any node for findings, captured source text, exact prompts and raw outputs. Export a JSON trace before closing. Imports are inspection-only.

    
file:// can be a secure context, but availability of WebGPU and persistent caching is browser-dependent. Android file managers may open content:// URLs or restricted viewers. This file probes WebGPU and caches rather than treating every local file as incompatible. If probes fail, serve the identical file over HTTPS or localhost. No server was deployed for this delivery. iOS support is best-effort.

    
Research basis

    
Inspected Browser-agent at commit 68d7f4c: README, architecture, engine contract, WebLLM adapter, Wikipedia lookup, prompt design and storage handling. This build directly bundles its WebLLM engine adapter, capability/storage helpers and Wikipedia tool—not the general HTTP agent loop.

    
  • WebLLM interface: asynchronous model loading and browser-local chat completion. Runtime pinned to @mlc-ai/web-llm 0.2.84, matching the repository lockfile.
  • WebGPU requirements and secure contexts: browser capability must be checked, including on file origins.
  • MediaWiki CORS: anonymous cross-origin search uses origin=*, followed by the repository’s Wikipedia summary endpoint. A labelled search snippet is the existing tool’s fallback.

    
Decisions for this build

    
  • One serial deterministic depth-first scheduler. A parent revisits only after all children resolve; blocked children leave it unresolved. Edges currently express parent–child decomposition, not semantic links or an assertion that all future graphs must be trees.
  • Both modes use the same graph mutation validator and episode runner. Simulation and live graphs are separate. Changing modes never relabels a simulated node as live.
  • A node visit has a fresh context. Multiple inference passes may request a tool and consume its result. Each pass resets the model’s conversation and receives only this node’s question, bounded child findings and captured evidence—not global chat history.
  • The harness assigns evidence IDs. Resolutions must cite IDs supplied in the current context. This checks provenance, not whether the quoted material logically proves the claim.
  • Context ceilings: last six resolved child findings (500 characters each), last five evidence excerpts (700 characters each). Omissions are counted in the exact context. These are prototype controls, not researched optimal settings.
  • Safety ceilings: 40 nodes, 60 visits, depth 6, two lookups and four model passes per visit; maximum 420 output tokens per pass. Hitting a ceiling stops unresolved work—it does not manufacture completion. Repeated questions remain visible.
  • Structured JSON generation is requested from WebLLM. Malformed output pauses with its raw trace. There are no invisible repair loops, verifier agents or automatic model escalation.
  • No general HTTP tools, arbitrary URLs, remote inference, API keys, model-authored HTML or code execution. Wikipedia queries and model downloads are the only intentional network traffic. Approval can be revoked between lookups.
  • App code, styles and WebLLM JavaScript are embedded. Model weights, tokenizers and compiled model WebAssembly remain external downloads. Cache API is preferred; IndexedDB is probed as a fallback. Offline live inference is not guaranteed.

    
What has and has not been verified

    
Verified: 15 automated graph and episode-runner tests; standalone file:// startup with normal browser web security; zero network requests during simulation; all three scenarios; pause and cancellation; touch selection, pan and zoom; export and inspect-only import; unsafe URL rejection and HTML rendered as text; separate mode state; missing-GPU recovery; 320 px, 390 px and 1280 px layouts, plus light and dark appearance. Wikipedia integration passed with controlled API responses. Both real Wikipedia endpoints responded to an HTTP client, but this environment’s browser could not complete a real Wikipedia request. The test machine supplied no usable WebGPU adapter, so real model loading, generation quality and an end-to-end run on a physical phone remain unverified.

    
Browser-agent’s measured tool-call reliability does not transfer to Tangle’s new decomposition prompts. Small local models may make poor decompositions, repeat themselves, misread evidence or fail to return useful findings. Keep the phone foregrounded; long sessions can consume battery and cause thermal throttling.

    
Data and privacy

    
Run state stays in memory until you export it. There is no analytics or automatic upload. Exports contain prompts, source excerpts and responses, so inspect them before sharing. Wikipedia sees requested query terms and your network address. Model hosts see model-download traffic. Live Wikipedia content remains attributed to its article and contributors under the applicable CC BY-SA licence.
